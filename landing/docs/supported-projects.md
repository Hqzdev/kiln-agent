# Kiln: какие проекты проверяем в первой версии

Задача: P0.6. Дата: 11 октября 2026.

## Поддерживаемые виды проектов

Первая приёмка проверяет работу с двумя видами существующих Git-репозиториев: Java/Gradle и Swift/SwiftUI. Другие проекты можно читать и обсуждать. Чтобы заявить поддержку выполнения работы в них, нужно отдельно настроить правила запуска команд и провести проверку качества.

| Проверочный проект | Планируемая папка | Система сборки | Для чего нужен |
| --- | --- | --- | --- |
| kiln-control-java-cart | fixtures/control/java-cart | Gradle Wrapper, JDK 25 | Исправление Java, тесты и вопрос коллеге о правилах расчёта |
| kiln-control-swift-state | fixtures/control/swift-state | SwiftPM и тестовая сборка Apple | Общий клиент, различие приёма команды и завершения работы, подключение к приложению |

Пока выбраны проекты и задания для них. Их исходники, настоящие исходные коммиты Git и сборки нужно подготовить в Q22.5 и A2.10. Этот документ не означает, что они уже созданы.

## Ошибка в проекте Java

Сумма корзины считается в целых минимальных денежных единицах, например в копейках: для каждой позиции количество умножается на цену, затем результаты складываются. У всех позиций одна валюта. Если число не помещается в допустимый диапазон, программа должна сообщить об ошибке, а не вернуть отрицательную сумму.

В проверочной версии цикл пропускает последнюю позицию:

```java
for (int i = 0; i < items.size() - 1; i++) {
    total += items.get(i).quantity() * items.get(i).unitPriceMinor();
}
```

| Корзина | Сумма с ошибкой | Правильная сумма |
| --- | --- | --- |
| Пустая | 0 | 0 |
| Одна позиция: 2 × 50 | 0 | 100 |
| Две позиции: 2 × 50, 1 × 75 | 100 | 175 |

Агент должен исправить расчёт, сохранить правила и добавить тесты для одной позиции, нескольких позиций и переполнения. Независимый проверяющий получает исходные требования и должен выявить пропуск последней позиции. При приёмке сохраняются ошибочная и исправленная попытки, их контрольные отпечатки (hash) и реальные коды завершения команд.

## Ошибка в проекте Swift

`acknowledged(commandId)` означает, что сервер принял команду. Статус задачи может стать `completed` только после события о завершении соответствующего рабочего запуска.

В проверочной версии обработчик подтверждения приёма слишком рано ставит на экране статус «Готово».

| События | Экран с ошибкой | Правильный экран |
| --- | --- | --- |
| Отправка → подтверждение приёма | «Готово» | «Принято, ожидает выполнения» |
| Подтверждение → начало работы | Может остаться «Готово» | «Выполняется» |
| Работа → ошибка | Уже показан ложный успех | «Ошибка» с причиной |
| Работа → завершение | «Готово» (completed) | «Готово» (completed) |

Нужно разделить подтверждение команды и состояние работы. Проверяются повторное подтверждение, события не по порядку и восстановление соединения. Разработчик интерфейса спрашивает разработчика сервера о формате события. Ответ сохраняется в канале и используется в обработчике состояния.

## Работа с исходным репозиторием

- До начала работы записывается исходная версия. Несохранённые изменения пользователя не должны потеряться.
- Исполнитель и интегратор работают в отдельных рабочих копиях Git (`worktree`).
- Проверочная задача не меняет main. Проверяются рабочая ветка и отдельные разрешения на commit и push.
- Сборка Swift/Xcode разрешена только после проверки ограничений среды запуска. Worktree разделяет файлы, но сам по себе не ограничивает доступ программы к системе.

## Что проверено в документе

Для обоих видов проектов указаны имя, планируемая папка, задание, известная ошибка, результат до и после исправления и условия приёмки. Расчёты Java проверяются арифметически, а сценарий Swift различает приём команды и завершение работы. Создание реальных проверочных проектов остаётся отдельной задачей.
