# Motes: малые специализированные агенты

Статус: целевое поведение продукта. Motes входят в Code как помощники Blot; их подключение к внешним сервисам планируется после базовой инженерной цепочки.

## Роль

Blot — основной собеседник пользователя и координатор Code-запуска. Он отвечает за итоговый план и результат. **Mote** — короткоживущая сессия агента с одной узкой целью, ограниченным контекстом, ограниченными инструментами и собственным бюджетом. **Motes** — такие сессии в совокупности.

Mote не является самостоятельным пользователем, не владеет запуском и не может менять цель, назначать себе задачи или расширять доступ. Он работает как дочерняя задача Blot и возвращает результат координатору. В Work Motes не запускаются.

## Когда Blot вызывает Mote

Blot оценивает запрос и может делегировать подзадачу, если у неё есть ясный результат и она может выполняться независимо: например, проверить отдельный модуль, найти подтверждения в подключённых документах или составить список действий по письмам и событиям календаря.

Blot не создаёт Mote для простого ответа, последовательных шагов с общей изменяемой областью, задачи без проверяемого результата или работы, где стоимость параллельного вызова выше ожидаемой пользы. Для изменения кода Code может назначить Mote ограниченный участок; интеграция и приёмка остаются под контролем Blot и обязательных независимых gates.

## Жизненный цикл

1. Blot создаёт дочернюю задачу с целью, критериями готовности, разрешёнными источниками, сроком и бюджетом.
2. Оркестратор выбирает профиль Mote, модель и allowlist инструментов по задаче и включённым пользователем интеграциям.
3. Mote получает только нужный контекст и свой `parentRunId`, `taskId` и `scope`. Он не получает всю историю чата, все проекты или секреты целиком.
4. Mote выполняет назначенную работу и возвращает структурированный отчёт: вывод, свидетельства и ссылки, неопределённость, фактические действия и незавершённое.
5. Blot проверяет соответствие критериям, свежесть источников и конфликты с другими результатами. Он использует подтверждённые части в общем ответе и показывает их происхождение.
6. По достижении лимита, отмене родителя, отозванном доступе или истечении срока Mote останавливается. Частичный результат сохраняется с соответствующим статусом.

Mote не запускает других Motes в первой архитектурной версии. Максимальная глубина делегирования — один уровень. Повтор создаёт новую попытку и не стирает прежний отчёт. Mote не может сам решить, что пользователь одобрил внешнее действие.

## Типы Motes

Тип — ограниченный профиль для назначения, а не отдельный класс программы. Он наследует только общие правила безопасности Blot и не наследует доступ других профилей.

| Тип | Работа | Типичный результат |
| --- | --- | --- |
| **Scout Mote** | Ищет в разрешённых источниках сведения по вопросу | Краткая сводка с ссылками, датами и неопределённостью |
| **Inbox Mote** | Находит в Gmail письма, требующие внимания, и извлекает возможные поручения | Кандидаты на задачи со ссылками на исходные письма; без отправки ответа |
| **Calendar Mote** | Сводит расписание и ищет свободные интервалы или конфликты | Предложенные интервалы и список конфликтов; без изменения календаря |
| **Drive Mote** | Ищет документы и извлекает сведения для задачи | Ответ с ссылками на файлы и фрагменты-основания |
| **Builder Mote** | Выполняет маленькую кодовую подзадачу в назначенной рабочей области | Diff и команды/проверки с фактическими результатами |
| **Checker Mote** | Проверяет ограниченное утверждение, diff или результат команды | Найденные дефекты либо проверенные критерии с evidence |

Названия описывают тип работы. Доступность профиля, модель, skill и инструменты задаются версионированным каталогом. Inbox, Calendar и Drive Motes доступны только после явного подключения соответствующего источника.

## Бюджет, доступ и наблюдаемость

Каждый Mote ограничен бюджетом токенов/стоимости, временем, числом вызовов инструментов и размером результата. До запуска Blot резервирует бюджет; после завершения фиксирует фактическое использование. Общий лимит Code-запуска включает бюджет дочерних задач. Неиспользованный резерв возвращается. Превышение бюджета останавливает Mote, а не создаёт бесконечные повторы.

Для каждого Mote сохраняются роль и версии инструкции/модели, постановка, parent/child связи, выбранные источники, выданные capabilities, действия, usage, длительность, итог и статус. Пользователь может открыть отчёт, увидеть, кто и на каком основании предложил результат. Секреты OAuth не включаются в его контекст или отчёт.

## Приёмка

- Blot не запускает Mote в Work; в Code он объясняет или показывает, какие подзадачи делегированы.
- Mote видит только назначенный scope; попытка чтения вне scope блокируется сервером.
- Mote с отменённым родителем, исчерпанным бюджетом или отозванным доступом прекращает новые действия.
- Каждый вывод из внешних источников имеет ссылку и дату; неподтверждённое остаётся предположением.
- Результаты двух Motes объединяются с устранением дублей и явным показом противоречий.
- Внешние изменения не выполняются только потому, что Mote предложил их.
- Простой запрос проходит без лишнего вызова Mote; делегирование имеет видимый расход и выигрыш по времени или полноте.
