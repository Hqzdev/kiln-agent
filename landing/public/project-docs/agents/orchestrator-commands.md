# Команды оркестратора

Документ описывает команды, которыми пользователь управляет запуском, и команды API, которые меняют состояние оркестрации. Здесь заданы целевые контракты и проверки; кроме отмеченных существующих операций, команды оркестратора являются спецификацией и требуют реализации.

## Уровни команд

- **Пользовательская команда** — действие или естественно-языковая просьба в интерфейсе. Она не обходит проверку прав и при неоднозначности создаёт опрос.
- **API-команда** — типизированное изменение состояния, которое сервер проверяет, сохраняет и связывает с событием.
- **Внутренняя команда оркестратора** — операция, доступная только доверенной службе оркестрации, например фактический запуск назначенной сессии.

Клиент не передаёт `actorId` как доказательство личности. Отправителя сервер получает из аутентифицированного соединения. Все изменения состояния выполняются атомарно с записью события.

## Команды пользователя

| Команда или действие | Требуемые параметры | Проверка перед выполнением | Ожидаемый ответ интерфейса |
| --- | --- | --- | --- |
| Отправить сообщение | Текст, проект/чат, при необходимости выбранный запуск | Пользователь имеет доступ к чату; сообщение не интерпретируется как разрешение на скрытое выполнение | Подтверждение доставки; если это только вопрос, ответ в чате без запуска инструментов |
| Создать запуск | Проект, цель, ограничения и вложения | Пользователь имеет право работать с проектом; цель непустая; команда не дублирует уже созданный запуск | Карточка нового запуска со статусом `DRAFT` или `PLANNING` и ссылкой на команду |
| Построить или пересобрать план | Запуск, актуальная версия требований, желаемый объём пересмотра | Запуск не завершён и не отменён; ревизия требований актуальна; пересборка сохраняет предыдущую версию плана | Предварительный план с задачами, зависимостями и блокировками |
| Утвердить план | ID и версия плана | Отправитель — пользователь с правом утверждать этот запуск; план прошёл проверку зависимостей и критериев готовности | Версия плана утверждена; запуск становится готов к назначению/выполнению |
| Назначить или сменить исполнителя | Задача, профиль агента, версия назначения, причина (при смене) | Профиль доступен в этом проекте; его capabilities покрывают задачу; зависимости позволяют работу; изменение не маскирует активную попытку | Новое назначение с профилем, основанием и текущим статусом |
| Запустить работу | Запуск или готовая задача; при необходимости версия назначения | План утверждён; зависимости завершены; профиль доступен; лимиты и разрешённые инструменты рассчитаны | Подтверждение постановки в очередь; затем пользователь видит активную сессию и события выполнения |
| Запросить ревью | Задача и ID точной версии результата | Результат зафиксирован; ревьюер не является автором; обязательные материалы для ревью доступны | Ревью поставлено в очередь для независимого проверяющего |
| Повторить задачу | Задача, основание повтора, при необходимости замечания ревью | Предыдущая попытка сохранена; задача не завершена; лимит повторов не исчерпан; причины исправимы | Создана новая попытка; история прошлых попыток и решений остаётся доступной |
| Ответить на опрос | ID запроса и один из трёх предложенных вариантов | Отправитель — доверенный пользователь; запрос открыт; вариант принадлежит именно этому запросу; версия актуальна | Ответ сохранён; запуск продолжает работу с заблокированного шага либо показывает оставшуюся причину блокировки |
| Приостановить запуск | Запуск и ожидаемая версия | Пользователь имеет право управлять запуском; запуск допускает паузу | Запуск в `paused`; безопасно останавливаются новые назначения и операции |
| Возобновить запуск | Запуск и ожидаемая версия | Пользователь имеет право управлять запуском; устранены блокирующие условия; план и разрешения актуальны | Запуск возобновлён с первой готовой операции |
| Отменить запуск | Запуск, ожидаемая версия, причина (опционально) | Пользователь имеет право отмены; подтверждён точный запуск; отмена допустима в текущем состоянии | Запуск в `cancelled`; выполняющиеся операции получают запрос остановки, история сохраняется |
| Принять итог запуска | Запуск и ID итогового артефакта/версии | Все обязательные gates пройдены для актуальных версий; принимающий имеет право; итог не изменился | Запуск завершается; показываются принятый итог, ограничения и подтверждения |
| Разрешить подготовленное внешнее действие | ID `PreparedAction`, точные аргументы и область разрешения | Действие показано пользователю; разрешение ограничено этим действием, проектом, сроком и числом применений | Разрешение выдано или отклонено; фактическое выполнение отображается отдельной операцией |

Пользователь может выразить запрос обычным текстом; интерфейс показывает его смысл и выполняет только команды, выведенные из запроса и прошедшие серверную авторизацию. Если есть несколько значимых трактовок, оркестратор отправляет один вопрос с ровно тремя вариантами ответа и ждёт выбор.

## API-команды

### Конверт команды

Для асинхронной оркестрации используется `/v1/commands` из будущего API-контракта. Расширение текущего `command.schema.json` новыми типами и серверная реализация ещё требуются.

```json
{
  "schemaVersion": 1,
  "commandId": "uuid",
  "type": "run.plan.generate",
  "projectId": "uuid",
  "payload": {
    "runId": "uuid",
    "expectedVersion": 0
  }
}
```

`commandId` — уникальный UUID для идемпотентности. `projectId` должен совпадать с проектом запуска и задачи. `expectedVersion` передаётся для изменяемого объекта. Пользователь или агент-инициатор определяется сервером, а не полем payload. Повтор с тем же `commandId` и тем же содержимым возвращает прежнюю квитанцию; повтор того же ID с другим содержимым отклоняется с `409`.

### Пользовательские API-команды

| Тип | Обязательный payload | Авторизация и проверки | Ответ после принятия |
| --- | --- | --- | --- |
| `run.create` *(есть в текущем API)* | `goal`, envelope `projectId`; опционально ограничения/вложения после расширения схемы | Участник проекта; цель проверена; текущая схема принимает только описанные поля | Legacy `/commands`: `200` и объект запуска; целевой `/v1/commands`: `202` квитанция и ID запуска; событие `run.created` |
| `run.status.change` *(есть в текущем API)* | `runId`, `expectedVersion`, `status` | Участник проекта; версия совпадает; переход разрешён машиной состояний | Legacy `/commands`: `200` и объект запуска; для новых клиентов предпочтительны команды намерения `run.pause`, `run.resume`, `run.cancel` |
| `specification.revision.create` *(есть в текущем API)* | `runId`, `content` | Участник проекта; запуск допускает новую ревизию; содержимое непустое | Legacy `/commands`: `200` и объект ревизии; целевой `/v1/commands`: `202` и событие о сохранённой ревизии |
| `run.plan.generate` | `runId`, `expectedVersion`, опционально `specificationRevisionId` | Пользователь-участник или уполномоченный менеджер; запуск не terminal; требования актуальны | `operationId`, версия плана и состояние `planning`; событие о плане |
| `run.plan.approve` | `runId`, `planId`, `planVersion`, `expectedVersion` | Только пользователь с правом утверждения; G1 пройден; утверждается точная версия | Новая версия запуска и статус `ready`; событие `run.plan_approved` |
| `task.create` *(есть в текущем API)* | `runId`, `title`, непустые `acceptanceCriteria`, `dependencyIds`; envelope `projectId` | Пользователь или менеджер проекта; запуск не terminal; ссылки принадлежат тому же запуску; граф ацикличен | Legacy `/commands`: `200` и объект задачи; целевой `/v1/commands`: `202` квитанция и `taskId`; событие `task.created` |
| `task.assign` | `runId`, `taskId`, `profileId`, `expectedVersion`, `reason` | Пользователь с правом ручного назначения или PM-сессия с `assignment.manage`; профиль активен и совместим; зависимости разрешают старт | `assignmentId`, новая версия задачи и статус назначения; событие `task.assigned` |
| `agent.start` *(внутренняя)* | `runId`, `taskId`, `assignmentId`, `expectedVersion` | Только OrchestratorService; назначение актуально; зависимости приняты; набор разрешённых capabilities вычислен сервером | `agentSessionId`, `operationId`, статус `queued`; событие `agent.session_started` после фактического старта |
| `review.request` | `runId`, `taskId`, `artifactId`, `artifactHash`, `expectedVersion` | OrchestratorService или авторизованный менеджер; результат неизменяем; ревьюер независим и доступен | `reviewId`, `reviewerProfileId`, статус `queued`; событие `review.requested` |
| `review.submit` *(внутренняя)* | `reviewId`, `artifactHash`, `decision`, `findings`, `evidenceRefs`, `expectedVersion` | Только назначенная reviewer-сессия; совпадает hash; автор и проверяющий различны; поля соответствуют схеме | Новая версия ревью и статус `accepted`, `changes_requested` или `blocked`; событие `review.submitted` |
| `task.retry` | `runId`, `taskId`, `previousAttemptId`, `reason`, `expectedVersion` | OrchestratorService или PM; прошлая попытка сохранена; есть исправимый отказ/замечание; бюджет повторов не исчерпан | `attemptId`, `attemptNumber`, статус `queued`; событие `task.retry_requested` |
| `user.ask.respond` | `runId`, `questionId`, `optionId`, `expectedVersion` | Только доверенный пользовательский клиент; запрос открыт; `optionId` содержится среди трёх вариантов | Ответ сохранён, блокировка пересчитана; событие `user.question_answered` |
| `run.pause` | `runId`, `expectedVersion`, опционально `reason` | Участник с правом управления; состояние допускает паузу | `202` квитанция; событие `run.pause_requested`, затем `run.paused` |
| `run.resume` | `runId`, `expectedVersion` | Участник с правом управления; нет неразрешённой блокировки; разрешения не истекли | `202` квитанция; событие `run.resume_requested`, затем `run.resumed` |
| `run.cancel` | `runId`, `expectedVersion`, опционально `reason` | Участник с правом отмены; подтверждён текущий запуск | `202` квитанция; событие `run.cancel_requested`, затем `run.cancelled` |
| `run.accept` | `runId`, `artifactId`, `artifactHash`, `expectedVersion` | Только пользователь с правом приёмки; все обязательные gates пройдены для этих версий; итог актуален | `202` квитанция; после проверки — `run.completed` с принятым hash |
| `permission.grant` | `preparedActionId`, точный scope, `expiresAt`, `maxUses` | Только доверенный пользователь; параметры совпадают с отображённым действием; проверка политики разрешений | `grantId` и квитанция; событие `permission.granted`; выполнение действия отдельной командой |

### Системные события, не являющиеся командами агента

`agent.start`, `review.submit` и операции фактического исполнения вызываются доверенными сервисами оркестратора с серверной идентичностью. Модель не может вызвать их напрямую, подделать инициатора или добавить capabilities в payload. Агент просит оркестратор о следующем шаге через результат своей работы; сервис отдельно проверяет переход состояния.

## Матрица команд и инструментов по ролям

Роль задаёт максимальный набор запросов, а не безусловный доступ. Для каждой сессии сервер пересекает этот набор с назначением, capabilities профиля, областью проекта, разрешениями пользователя и фактически подключёнными инструментами. Модель не вызывает API управления запуском напрямую: она возвращает результат или запрос действия, а доверенная служба проверяет и выполняет команду.

### Команды оркестрации, которые роль может запросить

| Роль | Разрешённые запросы | Только через оркестратор или пользователь | Запрещено роли |
| --- | --- | --- | --- |
| Product Lead | Предложить уточнение цели/требований; запросить `user.ask` при блокировке | Создание ревизии требований — только после подтверждения пользователя | Самостоятельно создавать/запускать run, утверждать план, выдавать разрешения, принимать результат |
| Project Manager | `run.plan.generate`, `task.create`, `task.assign`, `review.request`, `task.retry` | `agent.start` исполняет OrchestratorService после проверки плана, зависимостей и профиля | `run.plan.approve`, `run.create`, `run.accept`, `permission.grant`, `run.cancel` от имени пользователя |
| Tech Lead | Сообщить техническое решение и запросить уточнение через `user.ask` | Перепланирование и назначения — через PM или пользователя | Самостоятельно утверждать план/ревью, запускать сессии, менять права |
| Design Lead | Передать проектное решение и результат назначенной задачи; запросить `user.ask` при блокировке | Создание новой задачи — через PM или пользователя | Запускать/назначать других агентов, утверждать собственный результат, выдавать разрешения |
| Researcher | Передать вывод и ссылки; запросить `user.ask` при блокирующей неопределённости | Изменение требований или плана — через Product Lead/PM и пользователя | Создавать run, назначать задачи, утверждать ревью, выдавать разрешения |
| Backend Developer | Завершить назначенную попытку; сообщить о блокировке; запросить `task.retry` через PM | `agent.start` следующей попытки — только OrchestratorService | Самоназначаться, принимать собственное ревью, напрямую менять состояние run или права |
| Native Frontend Developer | Завершить назначенную попытку; сообщить о блокировке; запросить `task.retry` через PM | `agent.start` следующей попытки — только OrchestratorService | Самоназначаться, принимать собственное ревью, напрямую менять состояние run или права |
| Reviewer | `review.submit` только как назначенная reviewer-сессия, для указанного hash | Повторное назначение ревью — через оркестратор | Проверять свою попытку, изменять проверяемый результат, утверждать разрешения или принимать весь run |
| QA Engineer | Передать протокол качества и свидетельства; сообщить о блокировке | `task.retry` или изменение плана — через PM | Скрывать неуспешные проверки, принимать результат вместо Reviewer или пользователя |
| Security Engineer | Передать оценку и находки; сообщить о блокировке | Исправление, изменение разрешений и повтор — через PM/пользователя | Выдавать/расширять разрешения, выполнять неразрешённую эксплуатацию, принимать собственные исправления |
| Integrator | Запросить интеграцию принятых результатов и назначенные проверки | `agent.start` интеграционной сессии — через OrchestratorService; публикация — после `permission.grant` пользователя | Самостоятельно выполнять commit/push/публикацию без разрешения, принимать весь run, менять права |

`run.create`, `run.plan.approve`, `run.pause`, `run.resume`, `run.cancel`, `run.accept` и `permission.grant` принадлежат доверенным пользовательским командам. Ролевой агент может объяснить необходимость такого действия и подготовить точные данные, но не может отправить команду с пользовательской идентичностью.

### Инструменты по умолчанию и ролевые allowlist

Команды в таблице — имена из [границ инструментов](../tool-boundaries.md). Любая запись «по назначению» требует включённого инструмента и проверки конкретного назначения. Внешние MCP-инструменты не считаются частью базового набора Blot.

| Роль | Общий набор | Дополнительно только по назначению |
| --- | --- | --- |
| Product Lead | `project.read_file`, `project.search`, `artifact.read`, `task.message`, `user.ask` | MCP документации — чтение; никаких инструментов изменения |
| Project Manager | `project.read_file`, `project.search`, `artifact.read`, `task.message`, `user.ask` | `task.create` / `task.assign` только через проверяемые команды оркестрации; чтение каталога профилей |
| Tech Lead | `project.read_file`, `project.search`, `artifact.read`, `task.message`, `user.ask` | MCP Git/документации — чтение diff, контрактов и архитектурных материалов |
| Design Lead | `project.read_file`, `project.search`, `artifact.read`, `task.message`, `user.ask` | MCP дизайн-системы — чтение утверждённых компонентов и спецификаций |
| Researcher | `project.read_file`, `project.search`, `artifact.read`, `task.message`, `user.ask` | MCP поиска — поиск/чтение внешних источников; только с разрешённым доступом |
| Backend Developer | `project.read_file`, `project.search`, `artifact.read`, `task.message`, `user.ask` | `patch.prepare`, `patch.apply`, `process.run` по allowlist задачи |
| Native Frontend Developer | `project.read_file`, `project.search`, `artifact.read`, `task.message`, `user.ask` | `patch.prepare`, `patch.apply`, `process.run` по allowlist задачи |
| Reviewer | `project.read_file`, `project.search`, `artifact.read`, `task.message`, `user.ask` | `process.run` только для назначенных проверок; MCP Git только для чтения |
| QA Engineer | `project.read_file`, `project.search`, `artifact.read`, `task.message`, `user.ask` | `process.run` только с утверждёнными командами проверки и ограниченной средой |
| Security Engineer | `project.read_file`, `project.search`, `artifact.read`, `task.message`, `user.ask` | Разрешённый анализатор/сканер; `process.run` только для безопасных назначенных проверок |
| Integrator | `project.read_file`, `project.search`, `artifact.read`, `task.message`, `user.ask` | `patch.prepare`, `patch.apply`, `process.run`, `git.prepare_commit`, `git.prepare_push`; фактические `git.commit` и `git.push` — только с отдельным разрешением пользователя |

Для всех ролей список выше сужается до минимально необходимого. `patch.apply` и `process.run` не включаются только потому, что профиль имеет роль разработчика или QA. `user.ask` допустим только при реальной блокирующей неопределённости и всегда приостанавливает зависящую от ответа работу.

## Общий ответ и ошибки

Для асинхронной команды сервер возвращает `202 Accepted` с квитанцией:

```json
{
  "commandId": "uuid",
  "decision": "accepted",
  "operationId": "uuid",
  "entityId": "uuid"
}
```

`accepted` означает, что команда прошла первичную проверку и поставлена в обработку; это не означает, что операция завершилась успешно. Итог поступает как `ProjectEvent` и виден в состоянии запуска. Повтор команды возвращает прежнюю квитанцию.

Ошибки имеют общий вид `{code, message, details}`:

| HTTP | Код | Когда возвращается |
| --- | --- | --- |
| `400` | `validation` | Неизвестный тип, отсутствующее поле или неверный формат |
| `401` / `403` | `unauthenticated` / `forbidden` | Нет доверенной сессии или у отправителя нет нужного права |
| `404` | `not_found` | Проект, запуск, задача, профиль или артефакт не найден либо недоступен отправителю |
| `409` | `version_conflict`, `invalid_transition`, `duplicate_command_mismatch`, `gate_not_satisfied` | Устаревшая версия, недопустимый переход, повторный ID с другим содержимым или незакрытый gate |
| `429` | `budget_exceeded` | Достигнут лимит запуска, модели, инструмента или повторов |
| `503` | `temporarily_unavailable` | Временная недоступность хранилища, провайдера или очереди |
| `500` | `internal` | Неожиданная внутренняя ошибка без раскрытия секретных деталей |

Ошибка авторизации, версия и gate проверяются до постановки в очередь. Ошибка уже принятой асинхронной операции отражается в событии операции и состоянии запуска, а не маскируется как успешное завершение команды.

## Границы текущей реализации

Текущий `contracts/command.schema.json` и начальная реализация поддерживают только `project.create`, `run.create`, `run.status.change`, `specification.revision.create` и `task.create`. Остальные типы в таблице — целевой контракт оркестрации; их нужно добавить в схемы и обработчики отдельно. Не отправлять новые типы на текущий `/commands`: он отклонит неизвестные команды.
