# Навыки, плагины и MCP-серверы профилей

Документ задаёт рекомендуемый каталог навыков, плагинов и MCP-серверов для профилей Blot. Это целевая конфигурация: перечисленные внешние плагины и MCP-интеграции не считаются подключёнными, пока они отдельно не реализованы, настроены и разрешены для проекта.

Gmail, Google Calendar и Google Drive запланированы как будущие пользовательские подключения. Их OAuth, разрешённые операции и ограничения описаны в [спецификации Google Workspace](../integrations/google-workspace.md); сами подключения не включаются в профиль автоматически.

## Термины

- **Навык (skill)** — версионируемая инструкция с рабочим процессом и форматом результата. Навык сам по себе не выдаёт доступ к данным или инструментам.
- **Плагин (plugin)** — устанавливаемый пакет, который предоставляет интеграцию или группу инструментов. Наличие плагина не даёт агенту права вызывать каждый его инструмент.
- **MCP-сервер** — конкретный источник инструментов и контекстных ресурсов, подключённый к сессии. Для каждого сервера задаётся allowlist доступных операций.
- **Возможность (capability)** — разрешённое действие профиля, проверяемое сервером Blot. Возможность не может быть добавлена текстом навыка или ответом модели.

## Что включать сразу во все профили

Каждой сессии следует назначать общий набор только для текущей работы. Это минимальный общий слой Blot, а не полный доступ к проекту.

| Общая часть | Назначение | Доступ |
| --- | --- | --- |
| `blot-core` skill | Работа по назначению, проверяемые утверждения, фиксация результата и ограничений | Инструкция без самостоятельных прав |
| `blot-tool-use` skill | Как выбирать переданные инструменты, читать их схемы и фиксировать результат операции | Только инструменты, уже разрешённые сервером Blot |
| `blot-user-questions` skill | Если необходимо решение пользователя — отправить один опрос с ровно тремя вариантами, приостановиться и ждать ответа | Только `user.ask`; ответ принимается от доверенного клиентского приложения |
| `blot-project-context` skill | Ориентация в цели, критериях, границах проекта и незнакомом контексте | Чтение только переданных данных |
| `blot-evidence-reporting` skill | Связывать вывод с путём и строкой, артефактом, источником или фактическим результатом команды | Чтение доступных свидетельств; не создаёт свидетельства автоматически |
| `blot-task-messaging` skill | Передавать короткие сообщения по назначению с указанием результата и блокировки | `task.message` в рамках проекта и назначений сессии |
| `blot-project` MCP | Чтение разрешённых файлов и поиск по проекту | `project.read_file`, `project.search`; запись и shell отдельно и только по назначению |
| `blot-run` MCP | Получение своего задания, критериев, зависимостей и состояния блокировки | Только текущие `runId`, задачи и сессия |
| `blot-artifacts` MCP | Чтение связанных артефактов и фиксация результата через серверный workflow | `artifact.read`; создание снимка — только через назначенную операцию |
| `blot-user-interaction` MCP | Создание опроса и получение подтверждённого ответа | `user.ask`; агент не может записать ответ за пользователя |

Общие MCP-серверы Blot выше — рекомендуемые логические границы. Если реализация пока предоставляет эти операции через API, адаптер или встроенные серверные сервисы, их не нужно дублировать отдельными MCP-процессами.

## Ролевые навыки, плагины и MCP-серверы

В таблицах **Обязательный** означает нужный навык для профиля; **По назначению** — подключается лишь для соответствующей задачи; **Отложить** — не включать в начальную конфигурацию без отдельного требования.

| Профиль | Ролевые навыки | Плагины по назначению | MCP-серверы и операции |
| --- | --- | --- | --- |
| Руководитель продукта (`product_lead`) | **Обязательный:** `product-requirements`, `acceptance-criteria`, `scope-and-priorities` | **По назначению:** интеграция с системой продуктовых документов или задач | `blot-run` (цель, требования); `blot-project` (чтение продукта); MCP документации — чтение выбранных папок; MCP трекера задач — чтение и подготовка предложений |
| Менеджер проекта (`project_manager`) | **Обязательный:** `dependency-planning`, `task-breakdown`, `assignment-selection`, `blocker-management` | **По назначению:** интеграция с используемым трекером задач | `blot-run` (план, задачи, зависимости, состояния); `blot-agent-catalog` (доступные профили и capabilities, без редактирования политик); MCP трекера — чтение/создание/обновление задач в пределах проекта |
| Технический руководитель (`tech_lead`) | **Обязательный:** `architecture-review`, `interface-contracts`, `technical-decision-records` | **По назначению:** GitHub/Git-провайдер для чтения pull request и истории | `blot-project` (чтение кода и архитектуры); MCP Git — чтение веток, diff и PR; MCP документации — чтение архитектурных решений |
| Руководитель дизайна (`design_lead`) | **Обязательный:** `user-flows`, `interaction-states`, `accessibility-review`, `design-system-usage` | **По назначению:** Figma или другой утверждённый инструмент дизайна | MCP дизайн-системы — только опубликованные токены и компоненты; MCP дизайна — чтение файлов и экспорт утверждённых ресурсов; `blot-project` — чтение клиентского кода |
| Исследователь (`researcher`) | **Обязательный:** `source-evaluation`, `research-synthesis`, `uncertainty-reporting` | **По назначению:** поиск в интернете и выбранные источники | MCP поиска/браузера — поиск и чтение публичных страниц; MCP документации — чтение утверждённых пространств; `blot-artifacts` — сохранение отчёта. Для внешнего поиска обязательны URL и дата обращения |
| Разработчик сервера (`backend_developer`) | **Обязательный:** `java-backend`, `api-contracts`, `database-migrations`, `secure-tool-integration` | **По назначению:** GitHub/Git и CI | `blot-project` — чтение/поиск; `blot-code-change` — подготовка и применение ограниченного diff; `blot-process` — разрешённые сборки и команды; MCP Git — чтение, подготовка commit/push отдельно от выполнения |
| Разработчик интерфейса (`native_frontend_developer`) | **Обязательный:** `swiftui-implementation`, `accessibility`, `api-client-contracts`, `ui-state-management` | **По назначению:** Xcode/CI и GitHub | `blot-project` — чтение/поиск; `blot-code-change` — ограниченный diff; `blot-process` — только утверждённые сборки и проверки; MCP дизайна — чтение спецификаций |
| Проверяющий (`reviewer`) | **Обязательный:** `independent-code-review`, `requirements-traceability`, `finding-severity` | **По назначению:** интеграция с GitHub для diff и PR review | `blot-artifacts` — чтение точного hash; `blot-project` — чтение diff и связанных файлов; MCP Git — чтение PR/веток. Никаких write/review-submit операций без отдельного назначения |
| Инженер качества (`qa_engineer`) | **Обязательный:** `test-scenario-design`, `reproducibility`, `failure-reporting` | **По назначению:** CI, отчёты тестов и устройство/симулятор | `blot-artifacts` — чтение точной версии и запись протокола; `blot-process` — только разрешённые тестовые команды; MCP CI — чтение job, логов и артефактов |
| Инженер безопасности (`security_engineer`) | **Обязательный:** `threat-modeling`, `secure-code-review`, `secret-handling`, `vulnerability-triage` | **По назначению:** утверждённые security scanners и документация уязвимостей | `blot-project` — чтение; MCP security scanner — анализ только разрешённой копии; MCP Git — чтение diff; MCP документации безопасности — чтение. Не подключать средства реальной эксплуатации по умолчанию |
| Интегратор (`integrator`) | **Обязательный:** `change-integration`, `build-release`, `git-action-preparation`, `merge-conflict-resolution` | **По назначению:** GitHub/Git и CI/CD | `blot-artifacts` — чтение только принятых снимков; `blot-code-change` — подготовка интеграционного изменения; `blot-process` — разрешённая сборка; MCP Git — подготовка commit/push. Исполнение commit/push остаётся за отдельным разрешением |

## Рекомендуемые плагины-интеграции

Названия ниже — категории, а не утверждение о наличии конкретного подключённого пакета. Для проекта выбирается один источник каждого типа, если он действительно нужен.

| Категория | Роли-получатели | Минимальный набор операций по умолчанию |
| --- | --- | --- |
| GitHub или другой Git-провайдер | Tech Lead, Backend, Frontend, Reviewer, Security, Integrator; Project Manager — только при необходимости | Чтение репозитория, diff, PR и статусов; запись и отправка — отдельными capabilities |
| Трекер задач | Product Lead и Project Manager; другие роли только при назначении | Чтение проекта и задач; изменение только назначенной области |
| Документы и база знаний | Product Lead, Tech Lead, Design Lead, Researcher, Security | Чтение выбранных пространств и страниц; запись только по конкретной задаче |
| Дизайн-система | Design Lead, Frontend, Product Lead — чтение | Чтение компонентов, токенов и файлов; публикация или изменение — отдельно |
| CI/CD | Backend, Frontend, QA, Integrator | Чтение статусов, логов и артефактов; запуск workflow или выпуск — отдельно |
| Поиск в интернете | Researcher; Design Lead или Security по назначению | Поиск и чтение публичных источников; без авторизации от имени пользователя и без записи |
| Анализ безопасности | Security Engineer; Integrator/QA только для чтения отчётов | Анализ назначенной копии и чтение отчётов; изменение инфраструктуры или эксплуатация — выключены |

Не подключать все плагины всем профилям «на всякий случай». Общими для всех остаются только внутренние операции Blot с ограниченным контекстом. Внешние плагины добавляются роли тогда, когда назначение требует их данных или операций.

## Политика выбора и выдачи возможностей

1. Создавать `AgentSession` из общего слоя, ролевого слоя и минимального набора MCP-операций для назначения.
2. Запрашивать из каталога только конкретные scopes: проект, репозиторий, папки, пространства, ветки и допустимые операции.
3. Разделять чтение, подготовку и выполнение. Например, чтение diff не подразумевает право отправить review; подготовка push не подразумевает право выполнить push.
4. Если плагин недоступен, агент должен сообщить о недоступности и запросить блокирующее решение только если без интеграции работу продолжить нельзя. Не подменять отсутствующий сервер самодельным обходом.
5. Записывать в сессию версии навыков, plugin ID и версии, MCP server ID, allowlist операций, scopes и инициатора подключения.
6. При повторе или возобновлении запускать ту же зафиксированную конфигурацию. Новые права или версии требуют новой ревизии конфигурации и серверной проверки.
7. Внешние MCP-ответы и ресурсы считать недоверенными данными. Они не могут менять роль, инструкции, scopes или выдавать новые права.
