# Архитектура: как Swift и Java обмениваются данными

Задача: A2.11. Дата: 11 октября 2026. Документ готов. OpenAPI, JSON Schema и проверки совместимости ещё нужно создать.

Формат обмена нужен, чтобы приложения Mac и iPhone одинаково отправляли команды серверу и понимали его ответы.

## Способы подключения

На Mac используется HTTP/JSON по локальному адресу компьютера с проверкой отправителя. События приходят через SSE — постоянный поток обновлений от сервера. Wi-Fi использует защищённое соединение TLS и те же сценарии работы. Посредник BLE переводит сообщения Bluetooth с указанной версией формата в те же команды Java.

Сервер проверяет права независимо от способа доставки.

## Формат команды

```json
{
  "schemaVersion": 1,
  "commandId": "7a2d9e90-cc71-4d13-909e-86c3aa1a8cb1",
  "type": "run.create",
  "projectId": "8a0f0ac0-ae54-4f1f-afbc-157ad34bf7ce",
  "expectedVersion": 3,
  "payload": { "goal": "Исправить сумму корзины" }
}
```

`schemaVersion` — версия формата. Сервер проверяет её до выполнения команды. `commandId` — уникальный ID команды в журнале установки. `projectId` выбирает проект, `expectedVersion` указывает ожидаемую версию его данных, а `payload` содержит данные действия.

Сервер определяет actorId — отправителя — по проверенной сессии, а не по полю клиента. Повтор commandId с прежним содержимым возвращает прежнее подтверждение. Тот же ID с другим содержимым вызывает конфликт.

## Формат события

```json
{
  "schemaVersion": 1,
  "eventId": "90b8dcd8-949b-4726-88c3-f0e818559c33",
  "seq": "418",
  "projectId": "8a0f0ac0-ae54-4f1f-afbc-157ad34bf7ce",
  "runId": "bbf2a21a-4eb5-490e-86b6-3a43b451c81d",
  "entityId": "57a40946-c79b-4f3d-ab81-d8da50ad278f",
  "entityVersion": 4,
  "occurredAt": "2026-10-11T08:00:00Z",
  "type": "task.ready",
  "payload": { "reason": "dependencies_accepted" }
}
```

`eventId` — ID события, `seq` — его порядковый номер. Остальные поля указывают проект, запуск, объект, версию объекта, время и тип изменения.

Seq передаётся десятичной строкой. После чтения он преобразуется в 64-битное целое число и сравнивается как число. Сравнение строк запрещено: например, строка «100» может оказаться раньше «20». Строковый формат передачи защищает от потери точности у других обработчиков JSON.

Все UUID, даты и данные в примерах вымышлены для демонстрации формата. Это не события уже работающего проекта.

## Полное состояние и повтор событий

Полная копия состояния (`snapshot`) содержит данные для интерфейса и номер последнего учтённого события (`watermark`). Клиент принимает события только после этого номера, игнорирует повторные eventId и обнаруживает пропуски.

Если нужных событий уже нет в журнале, сервер требует получить новую полную копию. Переподключение не должно без причины сбрасывать выбранный узел графа.

## Разделы API

API охватывает состояние и совместимость сервера, проекты, разговоры, запуски, задачи, агентов, каналы и сообщения, результаты, ревью, разрешения, подготовленные действия Git, бюджеты, устройства, навыки и расписания.

Подтверждение приёма команды (`receipt`) содержит commandId, решение accepted/rejected, ID операции или запуска и ошибку при отказе. Оно не означает, что работа завершена. История читается страницами, большие файлы результатов — частями.

## Ошибки и действия клиента

| Код | Что сделать |
| --- | --- |
| VERSION_CONFLICT | Получить актуальное состояние перед новой командой |
| PERMISSION_REQUIRED | Открыть уже созданный запрос разрешения |
| PROTECTED_REF | Показать запрет, не пытаться обойти его |
| ACTION_INVALIDATED | Заново подготовить действие и запросить решение |
| DEVICE_REVOKED | Прекратить команды и подписки на события |
| SCHEMA_INCOMPATIBLE | Не выполнять команду неизвестного формата |
| REPLAY_UNAVAILABLE | Получить свежую полную копию состояния |
| OPERATION_UNKNOWN | Показать проверку фактического исхода; не повторять действие автоматически |

## Когда A2.11 можно закрыть

Нужно создать contracts/openapi.yaml и project-event.schema.json. Общие примеры проверяются по схеме и читаются обеими реализациями — Java и Swift. Конфликт версий, неизвестное событие и повтор команды должны пройти реальные тесты.
