# Архитектура: как разделён сервер Java

Задача: A2.4. Дата: 11 октября 2026. Документы и настройки подготовлены; задача целиком требует реализации пользователя.

## Что подготовлено без кода приложения

В backend подготовлены settings.gradle.kts, build.gradle.kts, Gradle Wrapper 9.1.0, каталог версий и четыре модуля. Для каждого создана структура src/main/java и src/test/java. Подключены зависимости между модулями, Java 25 и JUnit. Исходники Java помощника удалены. Сервер не реализован и не запускается; bootJar станет доступен после добавления пользовательского главного класса. Выполнение compileJava без исходников проверяет только конфигурацию, а не работоспособность сервера.

## Основное решение

Сервер запускается локально из пакета приложения macOS. Это одна программа, разделённая на модули. Она принимает проверенные команды, планирует работу, применяет правила проекта и доступа, выполняет инструменты и сохраняет данные. Отдельный облачный сервер Java не требуется.

Стрелка означает «использует»:

```text
api → application → core
infrastructure → application, core
api / место сборки компонентов → infrastructure
core → стандартная библиотека Java
```

## Модули

| Модуль | За что отвечает | Чего в нём не должно быть |
| --- | --- | --- |
| core | Основные объекты ProjectRun, Task, TaskAttempt, AgentSession, разрешения, контрольные отпечатки и состояния | Контроллеры Spring, JDBC и GigaChat SDK |
| application | Сценарии работы, планирование менеджера, ревью, интерфейсы правил доступа и хранилищ | Конкретные реализации JDBC и системных сервисов |
| infrastructure | Доступ к базе через JDBC, GigaChat, Git, запуск процессов и хранение результатов | Код интерфейса пользователя |
| api | HTTP, поток событий SSE, проверка отправителя, данных и ошибок; соединение компонентов | Повторная реализация основных правил внутри контроллеров |

## Сохранение изменений

Сценарий работы загружает объект с его версией, проверяет права и допустимость перехода состояния. Затем изменение и событие для отправки записываются одной транзакцией — либо вместе, либо никак. SSE отправляет только уже сохранённые события. Долгая внешняя операция не должна удерживать открытую транзакцию SQLite.

Точное описание действия (`PreparedAction`) и запись журнала сохраняются до выполнения. После него записывается известный результат. Если исход неизвестен, сначала нужно проверить фактическое состояние. Это позволяет восстановиться без повторного commit или push.

## Правила кода

У каждого класса одна ответственность. Внутреннее состояние закрыто от прямого изменения. Роли соединяются через настройки, зависимости передаются через явные интерфейсы. Контроллер только переводит сетевой запрос в вызов сценария работы.

AgentSession не наследуется от BackendDeveloper или Reviewer: роль задаётся конфигурацией.

## Когда A2.4 можно закрыть

Нужно создать settings.gradle.kts, build.gradle.kts, Gradle Wrapper и четыре модуля. Core должен собираться без Spring, SQLite и библиотек провайдера. Проверка импортов должна отклонять зависимость core → infrastructure.
