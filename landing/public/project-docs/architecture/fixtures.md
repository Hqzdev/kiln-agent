# Архитектура: общие тестовые данные

Задача: A2.10. Дата: 11 октября 2026. Документы и настройки подготовлены; задача целиком требует реализации пользователя.

Fixture — заранее подготовленный пример данных для теста. Java и Swift должны читать одинаковые файлы, чтобы проверять одни правила обмена.

## Что подготовлено без кода приложения

Все перечисленные примеры находятся в fixtures/contracts. ID, время и содержимое фиксированы, настоящих ключей и пользовательских данных нет. Файлы JSON можно использовать как общий источник для двух языков. Добавленные помощником тесты декодирования удалены. Примеры сами по себе не доказывают обработку повтора, пропуска, конфликта версии или BLE. Пользователь пишет декодеры и проверки на этих исходных файлах; задача целиком остаётся открытой.

## Набор примеров

| Файл | Ситуация | Ожидаемое поведение Java и Swift |
| --- | --- | --- |
| command-create-run.json | Первое задание | Одинаково прочитать commandId, projectId и goal |
| command-duplicate.json | Команда с прежним commandId пришла снова | Вернуть прежнее подтверждение, не выполнить действие второй раз |
| project-event.json | Событие правильного формата | Одинаково прочитать seq и версию объекта |
| snapshot-watermark.json | Получено полное исходное состояние | Читать следующие события после указанного номера watermark |
| event-gap.json | Пропущены события | Получить новую копию состояния или все недостающие события |
| event-duplicate.json | Событие с прежним eventId пришло снова | Не менять состояние второй раз |
| version-conflict.json | expectedVersion устарела | Сообщить о конфликте и получить актуальное состояние |
| approval-invalidated.json | Содержимое и его hash изменились | Не выполнять действие по старому разрешению |
| unknown-event.json | Неизвестный тип данных события | Обработать безопасно совместимым способом или явно сообщить о несовместимости |
| ble-fragments.json | Части BLE-сообщения потерялись или пришли не по порядку | Не применять неполное сообщение |
| provider-function-call.json | Модель запросила инструмент | Проверить аргументы и связать результат с ID вызова |
| operation-unknown.json | Сбой после внешнего действия | Сначала проверить фактический исход, затем решать вопрос повтора |

## Правила подготовки

ID, время и контрольные отпечатки (hash) фиксируются, чтобы тесты можно было повторить. Примеры не содержат настоящих ключей, путей пользовательских репозиториев и личной переписки. Тестовые секреты имеют узнаваемый префикс: по нему проверяется удаление секретов из вывода.

Обе реализации используют одни исходные JSON-файлы. Разные по содержимому копии для Java и Swift не подтверждают общий формат. Изменения схемы и её версии проходят ревью.

## Проверочные проекты

Выбраны Java-проект корзины и Swift-проект состояния команды из [описания поддерживаемых проектов](../supported-projects.md). В Q22.5 нужно создать версию с ошибкой, текст задания и ожидаемую проверку. Нужны исходный коммит base SHA, тест, который воспроизводит ошибку, и сценарий независимого ревью.

## Когда A2.10 можно закрыть

Все файлы должны существовать и одинаково читаться Java и Swift. Ошибочные примеры должны давать ожидаемый отказ. Сейчас готовы описание набора и сценарии. Тесты чтения данных самого продукта ещё не запускались.
