# Архитектура: правила кода и проверки зависимостей

Задача: A2.7. Дата: 11 октября 2026. Документ готов. Настройки и автоматические проверки ещё нужно создать.

## Основные правила

У класса одна ответственность, его внутреннее состояние закрыто. Нужное поведение собирается из компонентов, а не из цепочки наследования. Не допускаются мёртвый код, заглушки и методы, которые возвращают успех без выполненной работы. Для каждой ошибки должен быть понятный путь обработки.

| Часть кода | Правило |
| --- | --- |
| Java core | Не подключает Spring, JDBC и SDK провайдера; меняет состояние только через методы основных объектов |
| Java application | Получает зависимости через интерфейсы; не создаёт внешние реализации внутри сценария работы |
| Java api | Проверяет входные DTO и преобразует данные; контроллер не меняет состояние проекта напрямую |
| Swift Domain | Не подключает SwiftUI, AppKit, CoreBluetooth и конкретную сеть |
| Экран Swift | Показывает состояние и передаёт действия; не управляет сервисами внутри body |
| Граф | Подготовка данных и расположение узлов отделены от выбора на экране и соединения |

## Форматирование

Нужно настроить один форматировщик Java в Gradle и `.swift-format` для Swift. Версия форматировщика фиксируется вместе с остальными инструментами.

Проверка в CI сообщает об ошибке и не меняет файлы молча. Локальная команда форматирования меняет их явно.

Для числа повторов и тайм-аутов используются именованные константы. Комментарии объясняют важное правило, а не пересказывают соседнюю строку. Тестовый код не входит в сборку рабочего приложения.

## Проверка границ модулей

Автоматические проверки должны обнаруживать запрещённые импорты и циклические зависимости. Для Java можно проверять связи пакетов и модулей архитектурными тестами. Для Swift — отдельно собирать Domain и проверять зависимости целей сборки.

Пример ошибки: добавить в core импорт конкретного хранилища JDBC. Проверка обязана завершиться отказом. Второй пример — CoreBluetooth в KilnDomain. Пример допустимого изменения: заменить компонент провайдера через интерфейс, не меняя основные объекты проекта.

## Когда A2.7 можно закрыть

Нужно создать настройки форматировщиков и запускаемые проверки. Нарушение должно отклоняться локально и в CI, а код без нарушений — проходить. Пока этот документ только описывает правила и способы их проверки.
