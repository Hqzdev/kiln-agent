# Архитектура: общие части кода Swift

Задача: A2.3. Дата: 11 октября 2026. Документы и настройки подготовлены; задача целиком требует реализации пользователя.

Пакет Swift — отдельная часть кода, которую можно подключать к приложениям и проверять отдельно. Общие пакеты позволяют Mac и iPhone использовать одни модели и правила обмена с сервером.

## Что подготовлено без кода приложения

В packages/BlotDomain, BlotAPI, BlotDesign и BlotGraph подготовлены Package.swift с swift-tools-version 6.2 и минимумом macOS/iOS 26. Настроены локальные зависимости по схеме ниже. Созданы Sources и Tests. Эти папки намеренно не содержат заглушек. Пакеты пока не подключены к приложениям: Xcode не должен пытаться собрать пустую библиотеку. После добавления собственных исходников пользователь подключает готовые продукты к двум targets и запускает тесты.

## Зависимости

Стрелка означает «использует»:

```text
BlotMac / BlotIOS → BlotAPI, BlotDesign, BlotGraph, BlotDomain
BlotAPI          → BlotDomain
BlotGraph        → BlotDomain, BlotDesign
BlotDesign       → системные библиотеки интерфейса
BlotDomain       → Foundation
```

Циклические зависимости запрещены. BlotDomain не подключает SwiftUI, AppKit, CoreBluetooth, GigaChat SDK или конкретный компонент HTTP-соединения.

## Назначение пакетов

| Пакет | Что содержит | Что проверяется |
| --- | --- | --- |
| BlotDomain | ID, структуры передаваемых данных (DTO), состояния, неизменяемые копии состояния и события | Чтение общих тестовых данных и обновление состояния по событиям |
| BlotAPI | BackendClient, преобразование данных, интерфейсы соединений, подтверждения команд и поток событий | Тайм-ауты, пропуски и повторы событий, конфликты версий и совместимость |
| BlotDesign | Общие значения оформления, шрифты, темы и базовые компоненты | Состояния элементов и внешний вид в обеих темах |
| BlotGraph | Подготовка графа, расположение узлов, выбор и доступный список | Источники связей, устойчивое расположение и большие тестовые наборы |

## Как данные доходят до экрана

Соединение получает структуры данных и события. Хранилище состояния применяет их на `MainActor` — в контексте обновления интерфейса — и сообщает об изменениях. Экран получает только нужные данные и обработчики действий. Подписка на состояние не делает экран владельцем сетевого подключения.

Общий интерфейс соединения описывает отправку команды, получение полного состояния и поток событий. Сервисы процесса Mac и жизненного цикла iOS передаются приложением. Для чистого BlotDomain библиотека Bluetooth не нужна.

## Порядок реализации

Создать четыре файла Package.swift с минимальными версиями систем из P0.7. Явно зафиксировать версии зависимостей. Сначала собрать Domain, затем API и пакеты интерфейса. Предпросмотры используют тестовые данные и не обращаются к настоящему провайдеру или инструментам.

## Когда A2.3 можно закрыть

Все пакеты должны собираться, подключаться к обоим приложениям и проходить проверки допустимых импортов. Например, добавление SwiftUI в BlotDomain должно приводить к ошибке проверки границ.
