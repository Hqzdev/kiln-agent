## Ветки и изменения

В `main` хранится состояние, которое принимает пользователь. Агенты готовят изменения в рабочих ветках и отдельных рабочих копиях Git (`worktree`). За ветку, в которой объединяются результаты, отвечает один владелец.

Продукт запрещает прямые изменения main и основной ветки удалённого репозитория. Этот запрет действует на сервере независимо от интерфейса.

Commit сохраняет изменения локально, push отправляет их в удалённый репозиторий. Это разные действия с разными разрешениями. Перед commit фиксируются подготовленные изменения, исходный коммит base SHA и ветка. Перед push — удалённый репозиторий и полный refspec, то есть описание того, откуда и куда передаются изменения. Если содержимое поменялось, действие нужно подготовить и разрешить заново.

## Что хранить в Git

В Git входят исходники, описания состава и версий, Gradle Wrapper, схемы данных, тестовые примеры и документация. Не входят результаты сборки, рабочая база данных, локальные файлы пользователя, кэш редактора, ключи доступа, профили подписи и закрытые ключи.

`.gitignore` должен исключать `.next`, `node_modules`, `.build`, `DerivedData`, результаты и кэш Gradle, локальные экспорты и архивы, а также секретные файлы. Данные из Application Support не копируются в репозиторий.

## Проверка изменений

Ревью относится к конкретному коммиту, исходной версии или контрольному отпечатку файла (hash). Автор не может заменить собой обязательного независимого проверяющего. Исправленный результат проверяется заново. Материалы проверки содержат реальные команды и версии сборок.
