Hash — контрольный отпечаток содержимого. Он нужен, чтобы результат проверки нельзя было перенести на другую версию файлов.

## Какие части плана охвачены

P0 описывает требования и ограничения. D1 — дизайн всех экранов. A2 — структуру кода и правила обмена данными. J3–J13 — сервер Java, выполнение задач и инструменты. S14 — общий клиент Swift. M15 / I18 — интерфейсы Mac и iPhone. R16 / B17 — Wi-Fi и BLE. G19 — граф. H20 / E21 — расширения. Q22 / L23 — системные проверки и передача продукта.

Все 24 блока плана связаны хотя бы с одной строкой таблицы. Полный список из 405 ID задач есть в каталоге и полном техническом задании. Новое требование получает новый REQ ID и строку проверки до начала реализации.

## Что считать подтверждением

- Материал проверки содержит ID задачи и попытки, версию сборки, проверяемый hash, дату, команду или ручной сценарий, фактический результат и исполнителя.
- Фразы «тесты прошли» недостаточно: нужен результат, который относится к проверяемой версии.
- Реальные вызовы GigaChat и связь Wi-Fi/BLE на физических устройствах проверяются дополнительно. Тестовые данные их не заменяют.
- Интерфейс проверяется в обеих темах, в маленьком окне, с длинным русским текстом и с учётом доступности.
- Весь итоговый сценарий из 23 шагов фиксируется в Q22.12.

## Что проверено сейчас

Для всех REQ-01–18 указаны экран, команда или событие, задачи реализации и наблюдаемый результат. Требования не предполагают облачный сервер, инструменты на iPhone или обход защиты main. Проверена полнота документа; проверки самого продукта ещё предстоят.
