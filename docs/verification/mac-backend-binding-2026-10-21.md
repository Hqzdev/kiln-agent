# Подключение экранов Mac к backend

Дата: 21 октября 2026 года. Упакованное приложение не запускалось. Изменения проверены сборками, HTTP-сценарием и исполнением общего Swift-кода клиента.

## Реализовано

| Экран | Действие и источник данных |
| --- | --- |
| Новая задача / запуск Motes | Настоящие проекты, `run.create`, конечный бюджет, состояние планирования |
| План и задачи | Требования, критерии и покрытие из PLAN; `run.plan.approve`; задачи и зависимости из TASK |
| Управление работой | `run.pause`, `run.resume`, `run.stop`, `run.steer`, `run.accept`, `task.retry` |
| Команда | Отдельные AGENT_SESSION, Motes и причины ожидания; MESSAGE по каналам; INBOX с фактическим подтверждением обработки |
| Вопросы и разрешения | `user.answer`, `permission.grant/deny/revoke`; точные аргументы, исходный коммит и hash действия |
| Результаты | Неизменяемые артефакты, чтение содержимого частями, настоящий patch, REVIEW с hash и замечаниями, TOOL_OPERATION с результатами |
| Git | Отдельные `git.prepare_commit`, `git.prepare_push`, `permission.grant`, `git.execute`; сверка неизвестного исхода |
| Граф | Назначения, родительские сессии, сообщения, ревью и зависимости; каждая связь открывает свою сохранённую запись |
| Навыки | `skill.save/delete`, версия, включение, роли и область проекта/аккаунта |
| Расписания | `automation.save/delete/run_now`, timezone, время, дни недели, бюджет; сохранённая история настоящих запусков |

Неподдерживаемые варианты из прежних демоэкранов, например триггеры GitHub и выдача прав через навык, больше не предлагаются. Переименование и копирование истории Code не реализованы серверным контрактом; соответствующие прежние локальные действия выключены. Цель можно уточнять через новую ревизию требований.

## Состояние и надёжность

`LiveWorkspace`, `WorkspaceRecords`, `WorkspaceCommands` и `WorkspaceGraph` находятся в `packages/BlotAPI`. SwiftUI читает подтверждённые сервером записи. Сетевой клиент передаётся через конструктор. Источник не хранит второй независимый набор статусов задач.

Начальная загрузка получает snapshot, затем продолжает SSE от watermark. Из события читается актуальная запись по ID. Старый ответ не заменяет более новую версию. Удаление проекта убирает его дочерние записи из кэша. Смена аккаунта сбрасывает записи, очередь UI, выбранные элементы, навигацию и локальные источники.

После потери ответа команда повторяется с исходным ID, payload и ожидаемой версией. Подтверждённый отказ завершает эту попытку; неопределённый исход остаётся для повторения. Сохранённая очередь восстанавливается при входе, новые действия до завершения восстановления блокируются. Ошибка сети видна пользователю.

## Проверки

- Java: 49 тестов, ошибок и пропусков нет. `spotlessCheck`, strict dependency verification и `:api:bootJar` успешны.
- Новый настоящий HTTP-сценарий: подключить временный Git-проект → создать запуск → сохранить управляемый план → принять → пауза → продолжение → остановка → создать/изменить навык → создать расписание → вручную запустить → повторить тот же commandId. Повтор оставляет один запуск и одну запись истории. Чужой аккаунт не читает расписание.
- Swift BlotAPI: 23 теста. Snapshot этого Java HTTP-сценария загружается теми же `WorkspaceRecords`, которые используют экраны Mac.
- Проверены реальные переходы клиентского состояния snapshot → SSE → GET записи, обрыв связи, исходный payload при повторе, версия кэша, удаление проекта и смена аккаунта.
- Граф проверен с двумя сессиями одной роли, назначением, входящим сообщением, ревью и зависимостью. У каждой связи существует запись-источник; чужой запуск не попадает в граф.
- SSE отдельно проверен с LF/CRLF/CR, комментариями, разделителями, UTF-8, многострочным data, неполным событием и ограничением размера.
- Mac Debug arm64 и iOS Debug для Simulator собираются с `CODE_SIGNING_ALLOWED=NO`. Запуск приложения и визуальная проверка не проводились.

Команды и логи:

```sh
backend/gradlew --offline --no-daemon -p backend --dependency-verification=strict spotlessCheck check :api:bootJar
BLOT_HTTP_FIXTURES="$PWD/.build/http-fixtures" swift test --package-path packages/BlotAPI
xcodebuild -quiet -project apps/Blot.xcodeproj -scheme BlotMac -configuration Debug -destination 'platform=macOS,arch=arm64' -derivedDataPath .build/xcode CODE_SIGNING_ALLOWED=NO build
xcodebuild -quiet -project apps/Blot.xcodeproj -scheme BlotIOS -configuration Debug -destination 'generic/platform=iOS Simulator' -derivedDataPath .build/xcode-ios CODE_SIGNING_ALLOWED=NO build
```

## Оставшаяся приёмка

Нужны настоящие SMTP/GigaChat, подготовленная VM с инструментами, физический iPhone и подписанный запуск приложения. Без этого нельзя подтвердить реальное выполнение задач моделью, сборки внутри VM, транспорт BLE/Wi-Fi и поведение JVM/JNI в App Sandbox. Эти проверки не подменены демонстрационными результатами.
