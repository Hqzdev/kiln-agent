# Blot: кто делает работу и кто её принимает

Задача: P0.4. Дата: 11 октября 2026.

## Роли команды

| Роль | За что отвечает | Что не может делать сама |
| --- | --- | --- |
| Руководитель продукта (Product Lead / CEO) | Цель, требования и итог для пользователя | Отменять правила доступа инструментов |
| Менеджер проекта (Project Manager) | План зависимостей, назначения, блокировки и пересмотр плана | Принимать свои изменения без обязательной проверки |
| Технический руководитель (Tech Lead) | Архитектура и решение технических споров | Пропускать обязательную проверку качества |
| Руководитель дизайна (Design Lead / UI-UX) | Макеты, состояния экранов и взаимодействия | Давать системные права через дизайн |
| Исследователь (Researcher) | Факты с источниками и проверкой актуальности | Записывать предположение как доказанный факт |
| Разработчик сервера (Backend Developer) | Модули Java и результаты их проверки | Одобрять собственное обязательное ревью |
| Разработчик интерфейса (Native Frontend Developer) | Клиент SwiftUI и обмен с сервером | Переносить выполнение серверных решений на телефон |
| Проверяющий (Reviewer) | Замечания и решение по точной версии результата | Менять уже принятую копию результата |
| Инженер качества (QA Engineer) | Проверка сценариев и запись результатов | Удалять проверку, чтобы скрыть ошибку |
| Инженер безопасности (Security Engineer) | Правила доступа, секреты, доверие и изоляция | Разрешать агентам одобрять свои действия |
| Интегратор (Integrator / DevOps) | Объединение результатов, сборка и поставка | Делать push без действующего разрешения пользователя |

Роль задаётся настройками и списком доступных действий. Для каждой роли не создаётся подкласс Agent. Права сессии ограничены одновременно ролью, проектом, устройством и действующим разрешением: действие должно подходить под все эти ограничения.

## Обязательные этапы проверки

Этап называется gate: пока его условия не выполнены, переходить дальше нельзя. Hash — контрольный отпечаток содержимого, по которому определяется точная версия результата.

| Этап | Что поступает на проверку | Условие перехода | Что сохраняется |
| --- | --- | --- | --- |
| G1: план | Цель и версия требований | Нет циклических зависимостей, у задач есть критерии готовности | Версия плана и результат его проверки |
| G2: работа автора | Попытка выполнения задачи (TaskAttempt) | Подготовлена неизменяемая копия результата | Hash, список изменений, команды и коды завершения |
| G3: независимое ревью | Результат G2 | Проверяющий не является автором, обязательные замечания закрыты | Решение и замечания |
| G4: объединение | Принятые результаты | Конфликты исправлены, общий результат проверен | Hash объединённой версии и вывод тестов |
| G5: безопасность и качество | Результат G4 | Пройдены обязательные проверки задачи | Протокол с указанием версии |
| G6: действия Git | Подготовленное действие (PreparedAction) | Аргументы точны, разрешение пользователя действует | Разрешение и commit SHA или удалённая ссылка |
| G7: завершение запуска | Все обязательные задачи | Все проверки относятся к текущим версиям результатов | Итог, ограничения и ссылки на подтверждающие материалы |

G6 нужен, если задание включает commit или push. Отказ не удаляет готовые изменения. В итоге должно быть прямо сказано, что сохранение или отправка не выполнены.

## Если проверяющий попросил исправления

Автор создаёт попытку A1 с hash H1. Проверяющий R1 оставляет замечание F1. Автор делает новую попытку A2 с hash H2. Решение по H1 не действует для H2. Проверяющий повторно проверяет F1 и выполняет остальные обязательные проверки изменённой части.

При споре исполнитель не повышает себе права. Менеджер фиксирует блокировку, технический руководитель решает техническую часть, а пользователь решает, расширять ли область разрешения.

## Что проверено в документе

Автор, проверяющий, инженер качества и пользователь имеют разные обязанности. Самопроверка не заменяет G3. Принятый результат связан с точным hash и материалами проверки. При открытом обязательном замечании запуск не проходит G7.
