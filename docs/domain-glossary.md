# Blot: словарь основных понятий

Задача: P0.2. Дата: 11 октября 2026.

Точные имена типов оставлены для разработчиков. В таблице объясняется, что они означают и кто отвечает за изменения.

## Объекты проекта

| Название в коде | Простое объяснение | Кто изменяет |
| --- | --- | --- |
| Project | Репозиторий, настройки, память и папки, к которым разрешён доступ | Сервисы работы с проектом |
| ProjectRun | Один запуск работы над целью пользователя | Координатор выполнения |
| SpecificationRevision | Сохранённая версия требований, которую нельзя изменить задним числом | Приём задания и пересмотр плана |
| Task | Отдельная задача с условиями готовности и зависимостями | Менеджер проекта |
| TaskAttempt | Одна попытка выполнить задачу | Сервисы выполнения и проверки |
| TaskDependency | Результат другой задачи, без которого нельзя начать эту | Проверка плана |
| AgentProfile | Настройки специалиста: роль, инструкция, модель и предел доступных инструментов | Каталог профилей |
| AgentSession | Конкретный работающий специалист в конкретном запуске | Система выполнения |
| Assignment | Назначение специалиста на задачу | Менеджер проекта |
| Channel / Message | Канал переписки и сообщение со ссылками на источники | Сервисы сообщений |
| MemoryEntry | Факт или предположение с историей версий | Сервис памяти |
| ArtifactSnapshot | Неизменяемая копия результата с контрольным отпечатком hash и исходным коммитом base SHA | Сервис результатов |
| Review / Finding | Решение независимого проверяющего и его замечание | Сервисы проверки |
| ApprovalRequest | Запрос пользователю на разрешение конкретного действия | Сервис правил доступа |
| PermissionGrant | Разрешение с областью действия, сроком и числом применений | Проверенная команда пользователя |
| PreparedAction | Точное описание будущего действия и его аргументов | Подготовка инструмента |
| ToolOperation | Запись о выполнении подготовленного действия | Сервис выполнения |
| DeviceIdentity | Проверенная информация о доверенном устройстве | Сервис сопряжения |
| ProjectEvent | Сохранённое изменение с уникальным ID и порядковым номером seq | Журнал событий, записываемый вместе с изменением |
| Projection | Состояние, подготовленное для экрана или графа | Обработчик событий и сервис представлений |

## Что нужно различать

Профиль — это настройки, сессия — отдельный экземпляр специалиста. Один профиль может использоваться в нескольких сессиях. Одна сессия может получить несколько назначений. Новая попытка задачи не стирает предыдущую. Завершение задачи не требует удаления специалиста, а архивирование сессии не отменяет принятый результат.

Подтверждение HTTP (`acknowledgement`) означает только, что сервер принял команду. Успех инструмента подтверждает одну операцию. Принятое ревью подтверждает конкретную копию результата. Для завершения всего запуска нужно пройти все обязательные проверки.

Ревью не разрешает действия Git. Разрешение пользователя не заменяет независимое ревью. Сообщение коллеги не даёт новых прав и не заменяет управляющую команду.

## Состояния в коде

- Запуск: draft — черновик; planning — планирование; running — работа; waiting — ожидание; paused — пауза; reviewing — проверка; completed — завершён; failed — ошибка; cancelled — отменён; interrupted — прерван.
- Задача: planned — запланирована; ready — готова к началу; assigned — назначена; in_progress — выполняется; awaiting_review — ждёт проверки; changes_requested — нужны исправления; accepted — принята; blocked — заблокирована; failed — ошибка; cancelled — отменена.
- Сессия: idle — свободна; running — работает; waiting_for_message — ждёт сообщения; waiting_for_permission — ждёт разрешения; paused — на паузе; completed — завершена; failed — ошибка; archived — в архиве.
- Разрешение: pending — ожидает решения; granted — выдано; denied — отказ; revoked — отозвано; expired — срок истёк; invalidated — больше не подходит к действию.
- Операция: prepared — подготовлена; awaiting_permission — ждёт разрешения; running — выполняется; succeeded — успешна; failed — ошибка; cancelled — отменена; unknown — исход неизвестен.

Причина ожидания хранится отдельно: dependency — другая задача; message — сообщение; permission — разрешение; model_queue — очередь модели; runner_resource — ресурс для запуска команды; host_unavailable — Mac недоступен. Допустимые переходы определяются правилами объекта, а не текстом статуса.

## Правила, которые всегда должны выполняться

1. ID объекта остаётся прежним при изменении версии.
2. Состояние объекта нельзя менять напрямую: специальный метод сначала проверяет условия перехода.
3. Принятая задача ссылается на результат текущей попытки, принятый независимым проверяющим.
4. Изменение hash отменяет действие решения о предыдущей версии результата.
5. Подготовленное действие привязано к проекту, ветке, удалённому репозиторию, аргументам и исходной версии.
6. Если исход операции неизвестен, перед повтором нужно проверить, что произошло во внешней системе.
7. Автор и отправитель определяются по проверенной сессии, а не по недоверенному полю actorId.

## Примеры проверки

Профиль Backend Developer создаёт сессии S1 и S2 для задач T1 и T2. Изменение S1 не меняет профиль и контекст S2.

У задачи T1 первая попытка A1 получает замечание. Вторая попытка A2 принимается. A1 и замечание остаются в истории, но текущий принятый результат — A2.

Сервер принял команду, инструмент выполнил её, ревью ещё не закончено. Экран показывает ожидание проверки, а не завершение всего запуска.
